# tracks 安装包与多版本安装：全局 trac 与 trac install <path> — 验收标准

> 本文档为 SPEC-012（FR-0348..FR-0360、NFR-0159..NFR-0160）验收标准的唯一登记处；每条 AC 只写可从系统外部观察、可断言的通过条件。安装共存主链由 AC-FR0348-01 → AC-FR0349-01 → AC-FR0351-01 → AC-FR0352-01 → AC-FR0354-01 → AC-FR0353-01 → AC-FR0350-01 组合覆盖；OOB 防回退由 AC-FR0355-01 → AC-FR0356-01 → AC-FR0357-01 → AC-FR0358-01 → AC-FR0359-01 → AC-FR0360-01 组合覆盖。

## FR-0348 安装包内容完整

### AC-FR0348-01

- 从官方渠道获取对应版本安装包，其内容包含 skills 定义、templates 定义与默认 opencode.json，三者齐全、无缺项
- 按发布指引从该包完成安装后，全局安装与项目安装均具备完整工作能力，不因缺能力定义或缺默认配置而失败

### AC-FR0348-02

- 安装包中缺 skills/templates/默认 opencode.json 任一项时，该包判定为不合格，不进入可用版本候选

## FR-0349 全局 trac 可用

### AC-FR0349-01

- 全局安装完成后，在任意目录（含非项目目录）执行 `trac --help` 退出码为 0 并打印用法，不依赖仓库上下文
- 全局 `trac` 可作为安装与项目级服务入口调用后续子命令可用

### AC-FR0349-02

- 全局 `trac` 不在任意目录提供可连接的全局服务器：项目外请求服务不落到全局版本兜底（具体拒绝断言见 AC-FR0350-02）

## FR-0350 项目内服务器范围与运行形态

### AC-FR0350-01

- 在已安装 tracks 的项目目录内运行服务器，服务版本与该项目锁定版本一致（macOS/Linux 下发起 shell 退出后服务仍可连接，直至显式停止；Windows 下服务随启动进程存在而存在）
- 服务存活与其版本归属用户可观察到（连接后可见版本与项目对应，不串到全局版本）

### AC-FR0350-02

- 在未安装 tracks 的目录请求服务，服务端不提供服务：命令拒绝并指引到已安装项目目录或先执行安装，不以全局版本兜底、不伪装成已服务

## FR-0351 安装目标兼容空目录与已有项目

### AC-FR0351-01

- 通过本版支持的版本指定方式为目标目录指定版本并执行安装，目标目录实际装入该指定版本；全局版本与目标目录版本可不同（全局新、目标旧可共存）
- 未指定版本时安装仍给出确定版本（默认含义与显式参数形式不断言具体语法，只断言指定生效、缺省确定）

### AC-FR0351-02

- 对空目录执行安装，完成后该目录具备所装版本 tracks 工作能力
- 对正在开发的已有项目目录执行同一命令完成加装，不要求先清空或手工迁移

## FR-0352 覆盖安装与文件权属边界

### AC-FR0352-01

- 重复执行 `trac install <path>` 后，目标目录 tracks 自有文件（含 skills/templates 等）均为所装版本内容
- 用户项目文件（用户代码、文档、未跟踪改动）原样保留：内容逐字节不变，无新增冲突文件、无覆盖、无删除

### AC-FR0352-02

- 用户曾改动 tracks 自有文件后重装，tracks 自有文件被所装版本覆盖且不承诺保留改动；此覆盖不计为用户数据丢失、不触发恢复流程

## FR-0353 全局升级不波及锁定项目

### AC-FR0353-01

- 全局升级到新版本后，回到锁定旧版本的进行中项目，其 serve/run 等行为与升级前一致，可继续正常工作
- 该项目所用版本用户可观察到为旧版本（展示位置与文案不断言，只断言可观察且为旧版本）

### AC-FR0353-02

- 锁定旧版本的项目不被自动升级：升级后无自动迁移写入、无版本锁定变更，且其正常使用不被阻塞（可用命令返回可用结果而非升级要求）

## FR-0354 安装结果可验证与失败语义

### AC-FR0354-01

- 安装成功时目标目录具备所装版本 tracks 工作能力；安装失败时命令以非零退出并输出明确报错，不输出成功结论
- 失败后可重试或手工处理后重试；重复执行同一版本安装收敛到干净可用状态，不残留半成品导致后续可用命令持续失败

## FR-0355 阶段路径图可读

### AC-FR0355-01

- 在工作台打开运行时间线详情窗格，阶段路径以状态图呈现，已完成/当前/待开始可区分，并标注进出时间与门控等待
- 用户可从该图定位当前所处阶段，并以此进入所选阶段的实际过程查看（衔接 AC-FR0356-01）

### AC-FR0355-02

- 状态图渲染失败时呈现可读行降级，不空白、不伪造阶段与时间

## FR-0356 阶段实际工作流聚合可读

### AC-FR0356-01

- 选中某阶段查看其实际运行过程，呈现该驻留窗口的实际运行工作流聚合图，表达派发/人工动作/结论关系；重派折叠、超长折叠，末端为等待中的人工门
- 长事件链不淹没结论：聚合图可读，折叠阈值与排版的具体数值不断言

## FR-0357 按轮可查

### AC-FR0357-01

- 展开执行明细中某一轮，呈现该轮的输入/输出/思考过程与工具计数，可定位问题到轮
- 明细懒加载：大轮数下仍可导航可读，不一次性阻塞首屏（具体轮数阈值不断言）

### AC-FR0357-02

- 思考来源缺失的轮呈现可读说明，不伪报思考内容

## FR-0358 运行卡片与时间可读

### AC-FR0358-01

- 运行卡片以中文标签、人类单位耗时呈现状态、最近事件与耗时；节点起止时间以浏览器本地时间呈现；用户可读出当前状态与最近事件
- 门控等待时长真实计时，心跳不重置门控等待计时

## FR-0359 评审两决策

### AC-FR0359-01

- 评审门控等待人工裁决时，面板仅提供通过与退回两项决策：通过允许空意见完成，退回须填意见且意见先记为文档线程
- 通过/退回执行后门控可继续（执行/通过/退回/搁置闭环可走通）；空验收链隐藏而非空白

### AC-FR0359-02

- 正常流门控不堆模板化 reason/impact；异常门控仍保留；决策回读失败时内联提示，不伪报成功

## FR-0360 前端更新即时可见

### AC-FR0360-01

- 前端部署更新后用户普通刷新页面，文本静态资源为最新版本，样式与脚本不新旧混装
- API 路由语义不变；未变更文件仍可 304，不强制全量重下

## NFR-0159 后台服务持续性与前台诚实性

### AC-NFR0159-01

- macOS/Linux 下后台服务在发起终端退出后继续运行直至显式停止，显式停止后不再可连接
- Windows 下前台运行的生命周期与启动进程一致：进程结束则服务不可连接，不伪装成后台常驻

## NFR-0160 大轮数可读性能与缓存正确性

### AC-NFR0160-01

- 执行明细随轮数增长保持可导航可读：按需取轮、懒加载，不一次性阻塞首屏
- 静态资源即时性变更不改变 API 语义，不强制全量重下未变更文件；纯展示调参具体数值不断言
