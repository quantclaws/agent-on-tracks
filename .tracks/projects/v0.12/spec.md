# tracks 安装包与多版本安装：全局 trac 与 trac install <path> — 需求规格

> 本 spec 将 v0.12 story（S-001）落为可验证需求：在既有 `[project.scripts] trac` 与 `trac init/serve` 基线之上，新增官方安装包承诺与全局 `trac` 可用结果，新增 `trac install <path>` 跨目录版本安装与项目版本锁定共存，收敛服务器运行范围为仅项目目录内本版本服务（macOS/Linux 后台、Windows 前台），并把 v0.12 期间已上线验证的 OOB 工作台改进（BS-08 起）纳入跟踪防回退。容量：13 有效 FR（FR-0348..FR-0360，承接项目全局序号，<30 单版交付无需拆分；2 NFR 不计）。继承边界：`trac init` 脚手架幂等与路径提交、既有子命令语义（`start/run/triage/review/approve/return/status/validate/check/release/serve` 参数面）、v0.9 查询/命令/SSE 与 supervisor 串行、v0.10/v0.11 工作台 chrome 与单写路径（NFR-0157/NFR-0158）全部继承，本版不重写；本版新增的仅是安装包内容、全局可用、`install <path>`、版本锁定共存与项目内服务形态，OOB 部分仅锁已验证结果不重做设计。Out-of-Scope：进行中项目一键升级/迁移工具、Windows 后台服务、OOB 纯展示调参具体数值。

## 界面与入口

### E-01 全局安装与全局 trac

```
┌──────────────────────────────────┐
│ shell（任意目录）：                │
│  $ trac --help                     │
│  usage: trac init|start ...|serve … │
│  $ trac install <path> [--version] │
│ （全局命令：安装与项目级服务入口，  │
│  不提供全局服务器）                 │
└──────────────────────────────────┘
```

### E-02 trac install <path> 安装面

```
┌──────────────────────────────────┐
│ $ trac install ./my-proj           │
│ $ trac install /tmp/empty-dir      │
│ 成功：目标目录具备所装版本工作能力   │
│ 失败：明确报错、不伪报成功、可重试   │
└──────────────────────────────────┘
```

### E-03 项目内服务器运行

```
┌──────────────────────────────────┐
│ 已安装 tracks 的项目目录内：        │
│  macOS/Linux：后台服务              │
│  Windows：前台运行（暂不支持后台）   │
│ 项目外：不提供全局服务器（拒绝并指引）│
└──────────────────────────────────┘
```

### E-04 运行时间线与执行明细（OOB 继承面）

```
┌─────────────────────────────────────────────────┐
│ 时间线详情窗格：阶段路径状态图                   │
│ 所选阶段：实际运行工作流聚合图                   │
│ 执行明细：按轮展开 输入/输出/思考/工具计数        │
└─────────────────────────────────────────────────┘
```

### E-05 运行卡片与门控面板（OOB 继承面）

```
┌─────────────────────────────────────────────────┐
│ 运行卡片：中文标签/人类单位耗时/本地时间/阶段轨   │
│ 门控面板：建议操作默认动作                        │
│ 评审门：[通过] [退回]（退回须填意见）             │
└─────────────────────────────────────────────────┘
```

## 功能需求

### FR-0348 安装包内容完整

- **来源**：`BS-01` / `§3.1`
- **交付入口**：官方安装包 artifact（`E-01` 的安装来源）

WHEN 安装包构建完成，THE 系统 SHALL 提供包含 skills/templates 与默认 opencode.json 的官方安装包，使从该包全局安装与项目安装均获得完整工作能力，不缺能力定义与默认配置。

**用户可观察结果**：用户按发布指引获取对应版本安装包并安装后，全局与项目安装有完整来源；缺失任一承诺内容即安装包不合格。

### FR-0349 全局 trac 可用

- **来源**：`BS-02` / `§3.1`
- **交付入口**：`E-01`（shell 全局 `trac`，含 `--help`）

WHEN 全局安装完成，THE 系统 SHALL 在 shell 全局提供可执行的 `trac` 命令；在任意目录执行 `trac --help` 可用且零仓库依赖；该命令用作安装与项目级服务入口，不提供全局服务器。

**用户可观察结果**：用户在任意目录可用 `trac`；后续 `install` 与项目内服务都依赖它；全局命令不等同于全局服务器。

### FR-0350 项目内服务器范围与运行形态

- **来源**：`BS-03` / `§3.1`
- **交付入口**：`E-03`（项目目录内服务；沿既有 `serve` 面，不改变既有子命令名）

WHEN 用户在已安装 tracks 的项目目录下运行服务器，THE 系统 SHALL 以该项目锁定版本提供服务；在 macOS/Linux 下为后台服务（发起 shell 退出后继续运行，直至显式停止），在 Windows 下暂不支持后台服务（以前台运行，其生命周期随启动进程结束）。WHEN 用户在未安装 tracks 的目录请求服务，THE 系统 SHALL 不以全局版本兜底服务，而是拒绝并指引到已安装项目目录或先执行安装。

**用户可观察结果**：服务器只在项目目录内运行本项目版本；macOS/Linux 后台、Windows 前台；项目外无全局服务器可连。具体启停命令与可观测位置由后续阶段定，本条只锁范围与形态结果。

### FR-0351 安装目标兼容空目录与已有项目

- **来源**：`BS-04` / `§3.2`
- **交付入口**：`E-02`（`trac install <path>`）

WHEN 用户执行 `trac install <path>`，THE 系统 SHALL 同时支持空目录与正在开发的已有项目目录；`<path>` 为空目录时建成具备所装版本工作能力的项目，`<path>` 为已有项目时加装同一命令完成，不要求用户先清空或手工迁移。

> **Lex:** FR-0351 未覆盖 Story 要求的“可指定版本”：Story §3.2 明确“确定目标目录与版本（默认含义与显式版本形式由后续阶段定，本 story 只要求可指定版本）”，E-01 示意 trac install <path> [--version]，但 FR-0351 的 WHEN 仅写 trac install <path>，正文仅称“所装版本”，存在两种合理解读：A）始终装全局版本；B）可通过版本参数指定任意版本。仅 A 也能满足现有文字，但不满足 Seed #3“全局与指定目录装不同版本”与 Story“把指定版本装进目标项目”。请 Sage 在 FR-0351（或新增条目）显式锁定版本可指定性（指定则装指定版本、缺省含义与显式形式留待后续阶段），E-01 的 [--version] 仅为示意不构成合同。

**用户可观察结果**：空目录建项目与老项目加装同一命令完成。

### FR-0352 覆盖安装与文件权属边界

- **来源**：`BS-05` / `§3.2`
- **交付入口**：`E-02`（`trac install <path>` 覆盖语义）

WHEN 用户执行 `trac install <path>` 安装到目标目录，THE 系统 SHALL 覆盖安装 tracks 自有文件（含 skills/templates 等），且不触碰用户项目文件（用户代码、文档、未跟踪改动不受影响、无冲突）。用户暂不编辑 tracks 自有文件；若用户曾改动 tracks 自有文件，重装可覆盖且不承诺保留，此为使用政策而非需挽回的数据丢失。

**用户可观察结果**：重装后 tracks 自有文件为所装版本；用户项目文件原样保留。

### FR-0353 全局升级不波及锁定项目

- **来源**：`BS-06` / `BS-07` / `§3.3`
- **交付入口**：`E-02` 安装所建版本锁定 + `E-03` 项目内服务（版本可观察出口依附本条，展示位置与文案由后续阶段定）

WHEN 全局 tracks 升级到新版本，THE 系统 SHALL 保持已锁定旧版本的进行中项目仍用旧版本工作且行为不变；WHERE 项目锁定旧版本，THE 系统 SHALL 不自动升级该项目且不阻塞其正常使用（serve/run 等行为与升级前一致）。该项目所用版本用户可观察到；需要升级时由用户显式发起（升级迁移工具本身不在本次范围）。

**用户可观察结果**：新旧版本共存（全局新、旧项目旧）；旧项目可安心停留，不被强制升级、不被阻塞。

### FR-0354 安装结果可验证与失败语义

- **来源**：`§3.2`（失败时明确报错且不伪报成功，可重试）
- **交付入口**：`E-02`（安装结果出口，无独立入口，依附 FR-0351/FR-0352）

WHEN `trac install <path>` 执行结束，THE 系统 SHALL 给出明确成功或失败结论：成功时目标目录具备所装版本 tracks 工作能力（可用性级别）；失败时明确报错且不伪报成功，用户可重试或手工处理后重试；重复执行同一版本安装收敛到干净可用状态，不堆积半成品。

**用户可观察结果**：用户从不把失败安装误认为成功；失败可恢复。

### FR-0355 阶段路径图可读

- **来源**：`BS-08` / `§3.4`（OOB 已落地择要，不重做设计）
- **交付入口**：`E-04`（工作台时间线详情窗格）

WHEN 用户在工作台查看运行时间线详情窗格，THE 系统 SHALL 以状态图呈现阶段路径并标注已完成/当前/待开始、进出时间与门控等待；渲染失败时降级为可读行，不空白、不伪造。

**用户可观察结果**：用户可定位"我在流程哪里"；后续按轮下钻依赖此定位。

### FR-0356 阶段实际工作流聚合可读

- **来源**：`BS-09` / `§3.4`（OOB 已落地择要，不重做设计）
- **交付入口**：`E-04`（所选阶段的实际运行过程）

WHEN 用户选中某阶段查看其实际运行过程，THE 系统 SHALL 呈现该驻留窗口的实际运行工作流聚合图，表达派发/人工动作/结论关系；重派折叠、超长折叠，末端为等待中的人工门。具体折叠阈值与排版为已验证实现，不在本版重议数值。

**用户可观察结果**：用户可读"本阶段实际发生了什么"，长事件链不淹没结论。

### FR-0357 按轮可查

- **来源**：`BS-10` / `§3.4`（OOB 已落地择要，不重做设计）
- **交付入口**：`E-04`（执行明细按轮展开 + 按轮读接口沿既有）

WHEN 用户展开执行明细中某一轮，THE 系统 SHALL 呈现该轮的输入/输出/思考过程与工具计数；思考来源缺失时给出可读说明而不伪报；明细懒加载，大轮数仍可读可导航。

**用户可观察结果**：问题定位时"具体哪一轮说了什么/做了什么"可查。

### FR-0358 运行卡片与时间可读

- **来源**：`BS-11` / `§3.5`（OOB 已落地择要，不重做设计）
- **交付入口**：`E-05`（运行卡片与节点起止时间）

WHEN 用户查看运行卡片与节点起止时间，THE 系统 SHALL 以中文标签、人类单位耗时与浏览器本地时间呈现状态、最近事件与等待时长；心跳不重置门控等待计时；阶段轨轮播居中与标题全量显示为同一可读性承诺的实现细节，不另立需求。

**用户可观察结果**：门控处一眼可读；等待时长真实。

### FR-0359 评审两决策

- **来源**：`BS-12` / `§3.5`（OOB 已落地择要，不重做设计）
- **交付入口**：`E-05`（评审门控面板）

WHEN 评审门控等待人工裁决，THE 系统 SHALL 仅提供通过（空意见即可）与退回（须填意见，意见先记为文档线程）两项决策，并内联回读失败；正常流门控不堆模板化 reason/impact，异常门控仍保留。

**用户可观察结果**：门控处可决策、可继续（执行/通过/退回/搁置）；空验收链隐藏而非空白。

### FR-0360 前端更新即时可见

- **来源**：`BS-13` / `§3.5`（OOB 已落地择要，不重做设计）
- **交付入口**：工作台文本静态资源面（依附 FR-0355..FR-0359，无独立入口）

WHEN 前端部署更新后用户普通刷新页面，THE 系统 SHALL 提供最新文本静态资源；API 路由语义不变；未变更文件仍可 304，后续不得回退为启发式缓存掩盖已交付改进。

**用户可观察结果**：样式与脚本不新旧混装；陈旧缓存不掩盖工作台改进。

## 非功能需求

### NFR-0159 后台服务持续性与前台诚实性

- **来源**：`BS-03` / `§3.1`

macOS/Linux 下后台服务 SHALL 在发起终端退出后继续运行直至显式停止，且其存活与版本归属可观测；Windows 下前台运行 SHALL 诚实反映进程生命周期，不伪装成后台常驻。实现机制（守护形态）由设计选定，本条只锁可观察持续性。

### NFR-0160 大轮数可读性能与缓存正确性

- **来源**：`BS-10` / `BS-13` / `§3.4` / `§3.5`

执行明细在轮数增长时 SHALL 保持可导航可读（懒加载、按需取轮，不一次性阻塞首屏）；静态资源即时性变更 SHALL 不改变 API 语义，不强制全量重下未变更文件。纯展示调参具体数值不在本版锁定。
