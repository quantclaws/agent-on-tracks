## 2. 用户意图

- 用户想完成什么：一次装好 tracks 并在任何目录可用 `trac`（全局命令用于安装与项目级服务入口）；把指定版本装进目标项目（含空目录与进行中项目，覆盖安装 tracks 自有文件）；全局升级到新版本时，进行中项目仍停留在旧版本继续工作；在已安装 tracks 的项目目录下运行本项目版本的服务器（macOS/Linux 为后台服务，Windows 暂以前台运行、不支持后台）；另把 v0.12 期间已落地的 OOB 工作台改进择要纳入本 story 跟踪（运行工作流可观察、运行卡片与门控评审可读）。
- 当前哪里受阻：无官方安装包内容承诺（seed 要求打包 skills/templates 与默认 opencode.json）；无全局 `trac` 可用承诺；无 `trac install <path>` 跨目录安装能力（现有仅 `trac init` 在当前目录脚手架 `.tracks`）；版本号全局唯一，升级即全局生效，进行中项目无法停留旧版本；服务器运行范围未限定（按 Aaron 裁定：不存在全局服务器，只允许项目目录内运行，macOS/Linux 后台、Windows 暂不支持后台）；安装覆盖语义未限定（按 Aaron 裁定：覆盖安装、与用户项目文件无冲突、用户暂不编辑 tracks 自有文件）；另 OOB 工作台改进已上线验证但未进入 story，缺乏跟踪锚点。
- 完成后能看到什么结果：全局 shell 可执行 `trac`；目标目录具备所装版本的 tracks 工作能力并可在该目录运行本版本服务器（macOS/Linux 后台，Windows 前台）；全局升级后旧项目行为不变，可继续用旧版本工作；另工作台改进在 story 有行为种子对应（BS-08 起），后续 spec/acceptance 可引用。

## 3. 核心操作路径

### 3.1. 全局安装与全局 trac 可用

- **变更基线**：修改 — 当前已有 `[project.scripts] trac` 与 `dist/` wheel（0.11.0），`trac --help` 零依赖可用；但无安装包内容清单承诺，无全局命令可用承诺，无 install 子命令（`tracks/cli/main.py:_COMMANDS` 无 install）。本次新增官方安装承诺与全局可用结果；服务器运行范围按 Aaron 裁定收敛为仅项目目录内运行（不存在全局服务器），不改变现有子命令语义。
- **入口/触发**：用户按发布指引获取安装包并执行全局安装后，在任意目录执行 `trac`；需要运行服务器时进入已安装 tracks 的项目目录。

1. 获取对应版本的官方安装包（含 skills/templates 与默认的 opencode.json）。
2. 执行全局安装，使 `trac` 在 shell 全局可用（用作安装与项目级服务入口，不提供全局服务器）。
3. 在任意目录执行 `trac --help` 验证可用；进入已安装 tracks 的项目目录，用该项目版本运行服务器。
4. macOS/Linux 下服务器为后台服务；Windows 下暂不支持后台服务（以前台运行）。具体启停命令与可观测位置由后续阶段定，本 story 只锁定运行形态结果。

- **完成结果**：全局 `trac` 可用；服务器只在项目目录内运行本项目版本；用户可继续进入 3.2 安装项目版本，或直接服务已有项目。

### 3.2. 把指定版本安装到目标目录（trac install <path>）

- **变更基线**：新增（无新增路径）— 当前仅 `trac init` 在当前工作目录脚手架 `.tracks`（`tracks/cli/run_cmd.py:51-91`，幂等写 gitignore 与路径提交），无跨目录 `install <path>`，无版本选择，无空目录建项目语义。
- **入口/触发**：已装全局 `trac` 的用户在终端执行 `trac install <path>`，`<path>` 为正在开发的项目目录或空目录。

1. 确定目标目录与版本（默认含义与显式版本形式由后续阶段定，本 story 只要求“可指定版本”）。
2. 执行 `trac install <path>`，覆盖安装 tracks 自有文件（含 skills/templates 等）；安装不触碰用户项目文件（无冲突）；用户暂不编辑 tracks 自有文件。
3. 在目标目录验证该版本 tracks 可工作（可用性级别，不规定具体断言位置与文案）。

- **完成结果**：目标目录具备所装版本的 tracks 工作能力，可进入 3.3 的共存使用；覆盖语义见 BS-05；失败时明确报错且不伪报成功，用户可重试或手工处理后重试。

### 3.3. 全局与项目多版本共存

- **变更基线**：新增（无新增路径）— 当前无项目级版本锁定，版本号全局唯一（`pyproject.toml:version 0.11.0`），升级即全局生效，进行中项目无法停留旧版本。本次新增“项目锁定版本、全局升级不波及”的结果。
- **入口/触发**：用户全局升级到新版本后，回到仍锁定旧版本的进行中项目继续工作。

1. 全局安装并升级到新版本。
2. 回到锁定旧版本的进行中项目，用其锁定版本继续工作（serve/run 等行为与升级前一致）。
3. 可观察到该项目仍用旧版本（展示位置与文案由后续阶段定）。

- **完成结果**：新旧版本共存：全局新、旧项目旧；进行中项目不被强制升级；需要升级时由用户显式发起（升级迁移工具本身不在本次范围，见 §5）。

### 3.4. 运行工作流可观察（OOB 已落地择要）

- **变更基线**：修改 — 原阶段路径为文字/chip 行、阶段下为长事件链（无聚合、无按轮可查）；OOB 期间已改为阶段路径 mermaid 图、所选阶段实际运行工作流聚合图、聚合图下按轮执行明细与按轮读接口。本次把已验证结果纳入跟踪，不重做设计。
- **入口/触发**：用户在工作台打开一次运行的时间线/详情窗格查看阶段进展。

1. 查看阶段路径图确认所处阶段、进出时间与门控等待（回滚画回退边，渲染失败降级为可读行）。
2. 查看所选阶段的实际运行工作流聚合图确认派发/人工动作/结论（重派折叠、超长折叠，末端为等待中的人工门）。
3. 展开执行明细按轮查阅输入/输出/思考过程与工具计数定位问题（思考缺失时为可读说明，不伪报）。

- **完成结果**：用户可从“阶段在哪 → 本阶段实际发生了什么 → 具体哪一轮说了什么/做了什么”逐层下钻；明细懒加载，大轮数仍可读；可继续进入 3.5 做门控评审。

### 3.5. 运行卡片与门控评审可读（OOB 已落地择要）

- **变更基线**：修改 — 原运行卡片为 raw 事件/时长/20 字截断标题、门控面板为模板化 reason/impact 与分离式写操作；OOB 期间已改为中文可读卡片、本地时间、居中轮播阶段轨、简明门控与评审两决策。本次把已验证结果纳入跟踪。
- **入口/触发**：用户在工作台查看运行卡片并在人工门处做评审/执行动作。

1. 查看运行卡片确认状态、耗时、最近事件与本地时间，必要时用阶段轨轮播定位阶段。
2. 在门控面板按建议操作执行默认动作，或以“通过（空意见即可）/退回（须填意见，意见先记为文档线程）”完成评审门控。
3. 部署更新后普通刷新即见最新样式与脚本（文本静态资源不启发式缓存，API 语义不变）。

- **完成结果**：门控处可读、可决策、可继续（执行/通过/退回/搁置）；空验收链隐藏而非空白；前端更新不被陈旧缓存掩盖。

## 4. 行为种子

### BS-01 安装包内容完整

- EARS: `WHEN 安装包构建完成, THE 系统 SHALL 提供包含 skills/templates 与默认 opencode.json 的官方安装包`
- 来源: [3.1]
- 说明: 保证用户一次装好后全局与项目安装有完整来源，不缺能力定义与默认配置。

### BS-02 全局 trac 可用

- EARS: `WHEN 全局安装完成, THE 系统 SHALL 在 shell 全局提供可执行的 trac 命令（含 --help 可用，用作安装与项目级服务入口，不提供全局服务器）`
- 来源: [3.1 / Aaron 裁定：不存在全局 trac 服务器]
- 说明: 保护“到处可用”的安装结果，后续 install 与项目内 serve 都依赖它；明确全局命令不等同于全局服务器。

### BS-03 项目内服务器运行形态

- EARS: `WHEN 用户在已安装 tracks 的项目目录下运行服务器, THE 系统 SHALL 以该项目锁定版本提供服务；在 macOS/Linux 下为后台服务，在 Windows 下暂不支持后台服务（以前台运行）`
- 来源: [3.1 / Aaron 裁定 T-004：只允许项目目录内运行，macOS/Linux 后台、Windows 暂不支持后台]
- 说明: 锁定服务器运行范围与形态结果；具体启停命令与可观测位置由后续阶段定，不在本 story 展开。

### BS-04 安装目标兼容空目录与已有项目

- EARS: `WHEN 用户执行 trac install <path>, THE 系统 SHALL 同时支持空目录与正在开发的已有项目目录`
- 来源: [3.2]
- 说明: 保护 seed #4 的核心场景：空目录建项目与老项目加装同一命令完成。

### BS-05 覆盖安装 tracks 自有文件

- EARS: `WHEN 用户执行 trac install <path> 安装到目标目录, THE 系统 SHALL 覆盖安装 tracks 自有文件（含 skills/templates 等），不触碰用户项目文件；用户暂不编辑 tracks 自有文件`
- 来源: [3.2 / Aaron 裁定 T-003：覆盖安装、与用户项目文件无冲突、暂不允许用户编辑 tracks 自有文件]
- 说明: 锁定安装覆盖语义与文件权属边界：tracks 自有文件由安装覆盖，用户项目文件不受影响。

### BS-06 全局升级不改变锁定项目行为

- EARS: `WHEN 全局 tracks 升级到新版本, THE 系统 SHALL 保持已锁定旧版本的进行中项目仍用旧版本工作且行为不变`
- 来源: [3.3 / 约束：seed #3 明示]
- 说明: 多版本共存的核心价值：新版本试用与旧项目稳定互不干扰。

### BS-07 不强制升级进行中项目

- EARS: `WHERE 项目锁定旧版本, THE 系统 SHALL 不自动升级该项目且不阻塞其正常使用`
- 来源: [3.3 / 约束：seed #3“目前不支持开发中的项目升级”]
- 说明: 把“不支持升级”从现状描述转为产品承诺：旧项目可安心停留，需要升级由用户显式发起。

### BS-08 阶段路径图可读

- EARS: `WHEN 用户在工作台查看运行时间线详情窗格, THE 系统 SHALL 以状态图呈现阶段路径并标注已完成/当前/待开始、进出时间与门控等待（渲染失败降级为可读行）`
- 来源: [3.4 / OOB 择要：bf80e88 阶段路径 mermaid 图，已在 v0.12 运行验证]
- 说明: 保护“我在流程哪里”的可观察结果，后续按轮下钻都依赖此定位。

### BS-09 阶段实际工作流聚合可读

- EARS: `WHEN 用户选中某阶段查看其实际运行过程, THE 系统 SHALL 呈现该驻留窗口的实际运行工作流聚合图（重派折叠、超长折叠，末端为等待中的人工门）`
- 来源: [3.4 / OOB 择要：5cbb779 节点工作流、dbd11e0 状态聚合，已验证 M-STORY 5 节点/4 轮、v0.11 M-IMPL 折叠 81 派发]

### BS-10 按轮可查

- EARS: `WHEN 用户展开执行明细中某一轮, THE 系统 SHALL 呈现该轮的输入/输出/思考过程与工具计数；思考来源缺失时给出可读说明而不伪报`
- 来源: [3.4 / OOB 择要：2ef0314 按轮读接口、dbd11e0 明细手风琴，已验证懒加载与按命令缓存]

### BS-11 运行卡片与时间可读

### BS-12 评审两决策

- EARS: `WHEN 评审门控等待人工裁决, THE 系统 SHALL 仅提供通过（空意见即可）与退回（须填意见，意见先记为文档线程）两项决策并内联回读失败`
