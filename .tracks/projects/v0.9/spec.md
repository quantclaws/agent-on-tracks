## 状态与生命周期

### SM-01 命令生命周期（v0.9 新增）

未列出的状态转移即不允许；FR 描述可直接引用本清单行号（如 SM-01.2）。

1. （用户提交）→ `已受理`：命令先持久化入队并返回持久 `command_id`；未持久化即失败，不产生任何执行副作用（FR-0295）
2. `已受理` → `执行中`：唯一有效执行者认领（租约/代次绑定，FR-0296）
3. `执行中` → `已完成`：结构化结果落盘，用户可观察对应业务结果（SM-01.2）
4. `执行中` → `已失败`：结构化失败原因落盘（区分可恢复外部等待与不可恢复故障）
5. `执行中` → `已拒绝`：合法性/revision/digest/命令防护校验拒绝，无副作用（FR-0314、FR-0308、FR-0309）
6. 重复提交（相同幂等键）→ 返回原 `command_id` 与原结果，不新建命令、不重复执行人工决定（SM-01.1，FR-0295）
7. `执行中` → `已受理`（恢复）：worker/服务重启后按既有 WAL/pending 恢复重新认领；已完成的副作用经幂等键/reconcile 跳过（FR-0300）
8. `已失败`/`已拒绝` → `已受理`（重试）：仅经受控重试入口（FR-0311），不复活过期证据

### SM-02 运行等待与控制状态（v0.9 新增的用户可见投影维度）

1. `推进中` → `等待外部`：CI/模型额度/网络等外部条件未满足；持久化等待原因与下一次唤醒 `retry_at`（FR-0298/FR-0299）
2. `等待外部` → `推进中`：条件满足或到达 `retry_at` 且无生效 pause；恢复无人工唤醒
3. `推进中`/`等待外部` → `等待人工`：到达合法人工门（待办中心出现对应决定，FR-0307）；quota/CI 等待不得进入此状态
4. `等待人工` → `推进中`：对应决定经认证人工入口生效（FR-0308/FR-0309/FR-0310/FR-0311/FR-0312）
5. `推进中`/`等待外部` → `暂停请求已接收` → `已暂停`：Human pause 持久化（SM-02.4；FR-0310）；`暂停请求已接收` 与 `已暂停` 必须可区分显示，pause 优先于一切自动唤醒
6. `已暂停` → `推进中`（原合法位置）：Human resume，已完成工作保留
7. 终态：继承 v0.8 SM-01 终态（`RELEASED`/`CANCELLED`/`DELAYED`/`RETRY_TAIL` 等），本状态机不新增终态
8. 规范性说明：run 的阶段状态机完整继承 v0.8 SM-01（含 22 条转移），本状态机是 v0.9 新增的运行控制投影维度，不改变 v0.8 阶段状态机任何转移的合法性；两者不一致时以 Runtime 阶段状态机为唯一事实源

### SM-03 服务生命周期（v0.9 新增）

1. （启动命令）→ `启动中`：一条命令手动启动（不承诺守护/自启/日志轮转）
2. `启动中` → `健康`：健康检查通过（E-01 端点返回可用），工作台可访问
3. `健康` → `已停止`：用户显式停止；已登记运行状态持久化
4. 任意状态重启 → `启动中` → `健康`：重启后恢复已登记项目、进行中/等待中命令与等待状态（FR-0288/FR-0300）

## 功能需求

### FR-0288 Web 服务生命周期

- **来源**：`BS-01` / 规划 P01
- **交付入口**：`E-01`

THE 系统 SHALL 以单条命令手动启动/停止服务（本版不承诺守护进程、自启与日志轮转），提供健康检查端点；服务进程 SHALL 独立于浏览器存活（浏览器关闭不停止任何 run 的推进）；服务重启后 SHALL 恢复已登记的运行状态（已登记项目、进行中/等待中命令与等待状态，衔接 FR-0300）。

**用户可观察结果**：启动后 E-01 端点返回可用；关闭浏览器再重开，run 已推进到人工门/终态或等待态；服务重启后工作台状态连续可解释。

**关键失败/恢复边界**：健康检查未通过时工作台不得呈现"可用"假象；恢复失败须如实显示恢复中的命令与原因。

### FR-0289 项目登记与选择

- **来源**：`BS-02` / 规划 P02
- **交付入口**：`E-03`

THE 系统 SHALL 允许用户在许可范围内登记已有仓库/选择项目，界面 SHALL 显示项目归属（仓库与版本）以防对错误项目执行操作；登记状态 SHALL 持久化并在服务重启后恢复（FR-0288）。

**用户可观察结果**：登记后所有 run/操作绑定该项目归属；未登记项目不可被操作。

### FR-0290 运行环境就绪检查

- **来源**：`BS-02` / 规划 P03
- **交付入口**：`E-03`

THE 系统 SHALL 提供就绪检查并显示合同、harness/model、凭据引用与必需工具的就绪状态；未就绪项 SHALL 给出具体原因；沿用已配置环境（本版不做通用包管理 GUI）。就绪通过是创建/推进 run 的前置（未就绪时创建入口给出原因，不创建假 run）。

**用户可观察结果**：E-03 逐项就绪状态与未就绪原因；修复后重查通过即可继续创建 run。

### FR-0291 Feature story 创建

- **来源**：`BS-03` / 规划 P04
- **交付入口**：`E-04`

THE 系统 SHALL 允许用户经 UI 输入 story 内容与版本并提交创建 feature run；提交失败或重复提交 SHALL 有明确结果且不创建假 run；新 run SHALL 出现在总览列表并进入待澄清/待推进状态（SM-01.1/SM-01.6）。

**用户可观察结果**：提交返回持久 command_id 与 run 标识；重复/超时重试返回同一结果。

### FR-0292 两类 hotfix 入口

- **来源**：`BS-04` / 规划 P05
- **交付入口**：`E-04`

THE 系统 SHALL 经同一新建入口提供 post-release/dev 两类 hotfix（选择类别、issue 与目标上下文）；SHALL 复用既有前置检查（hotfix 前检语义继承 v0.8 hotfix 合同），前提不满足时不创建假 run 并给出原因；dev 旅程不生成公开 release（语义继承 v0.8 三旅程合同）。

**用户可观察结果**：两类 hotfix 经 Web 入口可完整运行；前置检查失败显示具体原因。

### FR-0293 需求澄清交互

- **来源**：`BS-05` / 规划 P06
- **交付入口**：`E-06`

THE 系统 SHALL 允许用户在 UI 阅读 Agent 提问与讨论历史并回复澄清问题；回复 SHALL 续接原 run（不新开无关联会话）；讨论线程的 resolved 权属遵循 FR-0314.4（请求 Human/指定评审者裁决的线程只能由被请求方经认证入口 resolved）。

**用户可观察结果**：回复后后台在同一 run 内继续推进；讨论历史完整可回溯。

### FR-0294 需求与设计材料审阅

- **来源**：`BS-06` / 规划 P07 / Human 裁定（技术选型增补，T-001）
- **交付入口**：`E-06`

THE 系统 SHALL 展示 story/spec/acceptance/design 的当前版本及变更（含 revision 标识），用户确认的对象 revision SHALL 明确显示；材料查看与基础编辑 SHALL 经指定文档前端组件承载（Vditor 基础集成：查看/编辑/版本对比；louke 扩展定制不实现），经 UI 编辑材料 SHALL 走既有修订流程产生新 revision、不得绕过 FR-0308 的批准绑定；审批行为由 FR-0308 统一承载（本条为审阅与确认对象语义）。

**用户可观察结果**：用户能指认自己审阅的是哪个 revision；批准时对象 revision 自动带入待批准条目。

### FR-0295 持久命令受理与去重

- **来源**：`BS-03` / 规划 P08 / 约束（story §5 S1）
- **交付入口**：`E-04`、`E-06`、`E-07`、`E-08`（所有命令入口共用同一命令服务）

THE 系统 SHALL 将 CLI 与 Web 经由同一命令服务受理命令：命令先持久化再执行（SM-01.1），每个命令返回持久 command_id；刷新/超时重试不得重复创建 run 或重复执行人工决定（SM-01.6）；查询类请求 SHALL 只读且不修改状态。HTTP 快速持久受理后由受控 worker 在边界处理，不在 HTTP handler 内直接运行长任务。

**用户可观察结果**：任何入口提交的相同请求产生等价命令/事件；HTTP 超时后重试不重复执行。

### FR-0296 单一有效执行者与活动 run 上限

- **来源**：`BS-07` / 规划 P09 / 约束（story §5 S2）
- **交付入口**：无独立入口，依附 FR-0295/FR-0297；可观察出口为 E-05 时间线

THE 系统 SHALL 保证同一 run 任一时刻只有一个有效执行者（租约/代次机制：命令队列 + lease + 防旧 worker 写入；租约过期后新 worker 获得新代次，旧 worker 迟到结果不得继续推动状态或发布）；CLI 与 Web SHALL 遵守同一仲裁，不双重 dispatch/publish。本版调度语义锁定（Human 裁定 T-001）：多 run 登记 + 同一时刻至多一个 run 活动串行推进 + hotfix 优先级换队——hotfix 紧急场景 SHALL 经显式可审计的换队满足（pause 活动 feature run → hotfix run 插队推进至发布 → resume feature，换队全程经命令服务受理并留审计记录）；真并发（worktree 隔离/多 worker 并行推进多 run）明确延期至后续版本；supervisor 设计 SHALL 预留 run 级隔离边界；并发 Agent 数由现有 Runtime 控制。

**用户可观察结果**：并发触发推进/重启 server/杀 worker 后无重复派发与越权写入；排队 run 状态可见；hotfix 换队全过程（pause/插队/resume）可审计。

### FR-0297 全阶段自动推进

- **来源**：`BS-07` / 规划 P10 / 约束（story §5：阶段语义继承 v0.8）
- **交付入口**：`E-05`（总览/详情观察）、`E-07`

WHEN run 处于非人工等待边界，THE 系统 SHALL 由后台按既有 Runtime 阶段状态机（v0.8 SM-01，含设计→测试→实施/RGR→验证→发布→归档全链）自动推进，无需用户逐条执行命令或保持会话在线；SHALL 在所有原合同要求的人工门可靠等待（用户未批准时不越过）。本条不重写任何阶段流程语义（继承边界见文首说明）。

**用户可观察结果**：关闭浏览器后 run 持续推进；重新打开可见推进轨迹；人工门前停住。

### FR-0298 外部等待与重试

- **来源**：`BS-08` / 规划 P11
- **交付入口**：`E-05`

WHEN run 等待 CI/Agent 产出/网络等外部条件，THE 系统 SHALL 持久化等待原因与下一次唤醒（retry_at）并如实显示（SM-02.1）；SHALL 区分可重试外部等待与不可恢复故障；无进展时不得热循环；服务重启后 retry_at SHALL 保留。

**用户可观察结果**：等待在 UI 显示为持久状态（原因 + 下次动作），不是瞬时错误。

### FR-0299 额度等待与续跑

- **来源**：`BS-08` / 规划 P12 / Maestro 钉死点（额度信号 spike）
- **交付入口**：`E-05`

THE 系统 SHALL 以 harness 返回的模型配额信号（provider 配额/限流类错误响应，既有 harness 层已检测 quota/rate-limit 信号）决定额度等待与恢复；已知 reset 时间 SHALL 持久保存并在到达后自动续跑（无人工唤醒）；未知 reset 时间 SHALL 有界退避探测（口径见 NFR-0152）且如实显示，不得编造倒计时；quota 等待不得冒充人工待办（FR-0307）。

**用户可观察结果**：额度不足 → 显示等待原因与探测计划；额度恢复 → 自动继续；UI 不出现虚假倒计时。

### FR-0300 崩溃重启恢复

- **来源**：`BS-09` / 规划 P13 / 约束（story §5 可靠性要求）
- **交付入口**：无独立入口，依附 FR-0288（E-01）与 FR-0295

WHEN 服务/worker 重启，THE 系统 SHALL 找回进行中/等待中的命令与等待状态（SM-01.7、SM-03.4）：未完成 effects SHALL 按既有 WAL/pending 恢复与 reconcile 机制处理（继承 v0.8 发布幂等/reconcile 合同），已完成的副作用经幂等键跳过，不得重复执行外部副作用、不得丢单。

**用户可观察结果**：注入一次可恢复外部等待与一次 worker/server 重启后，系统无需用户重新执行命令即继续推进，外部结果无重复。

### FR-0301 Run 列表与总览

- **来源**：`BS-10` / 规划 P14
- **交付入口**：`E-02`

THE 系统 SHALL 在总览显示当前/历史 run、版本、状态、需要人工处理的数量；状态查询 SHALL 只读（不修改状态）且 SHALL NOT 等待长任务结束（读路径独立事务，不阻塞推进）。

**用户可观察结果**：总览与实际 run 状态一致（同源事件/投影），打开即见。

### FR-0302 阶段与任务进度

- **来源**：`BS-10` / 规划 P15
- **交付入口**：`E-05`

THE 系统 SHALL 显示当前阶段、任务、已完成/剩余与质量状态；进度 SHALL 源于有依据的项目状态；测试数与需求完成率（验收子句闭合）SHALL 分别展示，不得把测试通过数当作需求完成率、不得编造百分比。

**用户可观察结果**："测试都绿"与"所有验收子句已闭合"两个维度可分别核对。

### FR-0303 Agent 执行状态

- **来源**：`BS-10`/`BS-12` / 规划 P16（story T-003 划界：run/任务级执行状态在范围内）
- **交付入口**：`E-05`

THE 系统 SHALL 展示各角色/任务级的执行状态（正在执行/等待/失败）及可用的执行日志关联；本条不含 Agent 会话内容/会话视图（story Out-of-Scope，T-003 划界）。

**用户可观察结果**：用户可看出"现在是谁在做什么/卡在哪"，并可跳到对应日志。

### FR-0304 AC 及验证证据视图

- **来源**：`BS-11` / 规划 P17
- **交付入口**：`E-05`

THE 系统 SHALL 展示从 AC 到测试 node、实际结果、候选与证据的关联链；缺失/过期/未审阅项 SHALL 明确标明；展示 SHALL 源于有依据的项目状态（不合成证据）。

**用户可观察结果**：发布/回拨判断可依据完整证据链追溯。

### FR-0305 事件与失败诊断

- **来源**：`BS-12` / 规划 P18
- **交付入口**：`E-05`

THE 系统 SHALL 提供事件时间线（可读时间线、错误、重试次数、阻断原因与下一步）；日志 SHALL 可定位到具体 run/command/task/AC；诊断信息 SHALL 来自同一事件源/投影（不维护仅在内存中的"运行中"事实）。

**用户可观察结果**：失败可解释（哪一步、为何、重试几次、下一步是什么）。

### FR-0306 实时状态与断线重连

- **来源**：`BS-13` / 规划 P19
- **交付入口**：`E-02`、`E-05`

THE 系统 SHALL 提供基于事件订阅的实时增量更新；浏览器断线重连后 SHALL 按游标补读事件，快照与事件 SHALL 一致，事件重复/乱序不得使 UI 倒退；实时订阅与历史补全 SHALL 共用同一事件源。

**用户可观察结果**：重连后看到单调一致的投影，无漏失或回退。

### FR-0307 人工待办中心

- **来源**：`BS-12` / 规划 P20
- **交付入口**：`E-07`

THE 系统 SHALL 集中展示当前合法且必须人工处理的决定（含理由与上下文，可跳转到对应操作入口）；quota/CI/网络等待 SHALL NOT 冒充人工待办；发布确认的提醒即由此承载（candidate 进入可发布状态即在待办中心出现，本版不另设提醒通道）。

**用户可观察结果**：待办清单只含真正需要人的决定，每项可直达操作入口。

### FR-0308 阶段批准与修订决定

- **来源**：`BS-06` / 规划 P21 / 约束（story §5 认证人工入口）
- **交付入口**：`E-06`、`E-07`

THE 系统 SHALL 允许原合同要求的非发布阶段审批（需求/spec/acceptance 等修订决定）经 UI 完成；每次批准 SHALL 绑定用户实际审阅的 revision，记录操作者、审阅 revision 与决定（可审计）；基于过期 revision 的批准 SHALL 被拒绝（复用既有人工批准 revision 校验语义，不直接 append human.approval）；批准 SHALL 只能来自认证人工入口（RP-01 #3）。

**用户可观察结果**：批准生效后自动推进下一阶段；过期批准被拒绝并提示当前 revision。

### FR-0309 发布预览与三择一决定

- **来源**：`BS-14` / 规划 P22 / 约束（story §3.6：继承 cmd_release 语义）
- **交付入口**：`E-08`

THE 系统 SHALL 在 candidate 所有门通过后提供 UI 发布预览审阅（含 digest 与过期状态提示）；用户 release/delay/return 决定 SHALL 绑定该 preview digest；过期 preview 的批准 SHALL 被拒绝（继承 v0.8 preview 绑定与 stale 语义）；release SHALL 只能由认证人工批准、后台不得代批（RP-01 #4）；release 经既有 authorization 与发布流程执行后，UI SHALL 显示真实 remote 结果并可查 AC 证据链；发布成功后 run 进入归档/收尾（继承 v0.8 M-PUBLISH/M-MILESTONE 语义）。

**用户可观察结果**：发布完成/延迟/退回均有明确终态与审计记录；已推送 tag/release 不会被回拨抹掉。

### FR-0310 暂停与继续

- **来源**：`BS-15` / 规划 P23
- **交付入口**：`E-07`（控制区）、`E-05`（状态显示）

WHEN 用户请求 pause，THE 系统 SHALL 持久化 pause 并显示"已接收 → 已暂停"两段状态（SM-02.5）；已生效的 pause SHALL 优先于一切自动唤醒（额度恢复/retry_at 到期均不得越过）；resume SHALL 从原合法位置继续并保留已完成工作。

**用户可观察结果**：pause 后无论外部条件如何变化，run 保持暂停直到明确 resume。

### FR-0311 失败后的受控重试

- **来源**：`BS-19` / 规划 P24 / 约束（story §5：继承 v0.8 repair/escape 合同）
- **交付入口**：`E-07`（控制区）、`E-05`（状态显示）

WHEN 可恢复失败的外部条件修复后，THE 系统 SHALL 提供经 UI 的受控重试，从原合法位置按既有 repair/escape 合同重新推进（SM-01.8）；重试 SHALL NOT 复活过期证据、SHALL NOT 绕过质量门或被拒绝的门槛、SHALL NOT 重复外部副作用；重试语义继承 v0.8 既有合同，本版仅经 Web 受控入口暴露。

**用户可观察结果**：条件修复后一次受控重试即从合法位置继续；无效重试（证据过期等）被拒绝并说明原因。

### FR-0312 阶段回拨

- **来源**：`BS-16` / 规划 P25 / 约束（story §3.7：继承 cmd_return 语义）
- **交付入口**：`E-05`（控制区）、`E-07`

THE 系统 SHALL 允许用户经 UI 发起阶段回拨：选择 Runtime 允许的上游阶段、查看将失效的证据与影响（含已发生的不可逆副作用清单）并确认；回拨 SHALL 按既有合法性校验执行（允许目标、不可逆操作确认、escape barrier 与证据 stale 规则继承 v0.8 SM-01.11/RP-01 #15）；屏障生效后旧 Agent 迟到结果 SHALL NOT 推进被回拨的流程，下游证据按规则失效并重验；阶段回拨不是撤销历史——已推送 tag/release 不会消失。

**用户可观察结果**：回拨后 run 按新决定重新推进；受影响证据标明失效；远端已发生副作用如实保留。

### FR-0313 放弃运行

- **来源**：`BS-16` / 规划 P26 / 约束（story §3.7：继承 v0.8 abandon 语义）
- **交付入口**：`E-07`（控制区）、`E-05`

THE 系统 SHALL 允许用户经 UI 受控 abandon/cancel：终止 SHALL 保留审计与已发生副作用，不把终止包装成成功、不假装撤销远端操作（继承 v0.8 CANCELLED 轻量终止语义：不删证据、零新增外部副作用）；退出/取消/真实不可恢复错误 SHALL 均有明确终态。

**用户可观察结果**：放弃后 run 停在明确的取消终态，审计与证据可查。

### FR-0314 人工身份与访问控制

- **来源**：`BS-17` / 规划 P27、S6 / Human 原则裁定（story §5 讨论线程裁决权属 / T-002）
- **交付入口**：`E-01`（认证入口）；约束覆盖所有命令入口（E-04/E-06/E-07/E-08）

1. THE 系统 SHALL 要求本机单用户认证的工作台访问边界（首版本机单用户鉴权；公网多租户不在范围），批准/命令/控制操作 SHALL 经认证入口提交（RP-01）。
2. HTTP 命令受理 SHALL 经命令防护校验：任意 shell SHALL NOT 可经 HTTP 提交执行；命令结构化提交，语义与 CLI 同一校验。
3. 后台与 Agent SHALL NOT 伪造人类批准/决定（RP-01 #9）；"认证人工入口"是批准真实性的前置。
4. 裁决权属（Human 原则裁定，须在 acceptance 演化为可验证规则）：请求 Human/指定评审者裁决的讨论线程，其 resolved 状态只能由被请求方经认证入口的真实响应触发，Agent 发起者自 resolve 此类线程视为无效；对应 v0.9 Web 待办中心/讨论界面的行为需求（与"人工批准只能来自认证人工入口"、BS-17 同族）。本条不接受"按设计可伪装"的君子约定长期存续。

**用户可观察结果**：未认证访问被拒绝；伪造决定不产生效果且被审计记录；越权的线程 resolved 无效。

### FR-0315 凭据与信息暴露边界

- **来源**：`BS-18` / 规划 P28、S6
- **交付入口**：无独立入口，依附全部用户可见表面（E-02..E-08 及日志/导出）

THE 系统 SHALL 使用受控凭据引用（凭据不出现明文）；UI/API/日志 SHALL NOT 泄露密钥；文件与产物读取 SHALL 限制在授权项目及证据范围内。

**用户可观察结果**：任何界面/日志/导出中凭据以受控引用呈现；越权读取被拒绝。

## 非功能需求

### NFR-0150 性能与资源口径

- **来源**：story §5 可靠性要求 / 规划可靠性要求（延迟/资源口径明确测量）

命令受理 SHALL 为持久化写入后即返回（HTTP 不等待执行完成）；本机单用户、单 run 推进负载下，交互查询（总览/详情/时间线）响应 P95 SHALL < 1 秒；读路径 SHALL 使用独立事务，SHALL NOT 阻塞推进写路径；服务常驻资源占用 SHALL 有界（无无界内存增长）；SQLite 单写者约束下的写入 SHALL 经统一命令服务串行化（不并发调用两个执行器假定可抢占）。

### NFR-0151 可靠性测试覆盖

- **来源**：story §7 风险 / 规划可靠性要求

以下场景 SHALL 有可执行测试覆盖：服务重启、断网、模型额度、重复/并发请求、并发 worker、UI 断线重连、旧 worker 迟到结果、人工 pause 与自动唤醒竞态；继承 v0.8 质量门与覆盖率门槛（v0.8 承诺仍失败的发布功能、AC/RGR 证据、宿主真实旅程与质量门不得挪入本版——继承边界见文首）。

### NFR-0152 等待探测与轮询上限（规格期锁定口径）

- **来源**：`BS-08` / 规划 P12 / 约束（story §5 锁定项）

外部等待的探测 SHALL 有界：指数退避，初始间隔与上限为服务配置项，发布默认值初始 60s、上限 15min；无进展时探测频率不得高于配置上限（不热循环）；已知 reset 时间精确唤醒（受 pause 优先约束）。UI 实时通道优先推送；轮询回退模式默认间隔 5s，空闲上限 60s（同为配置项默认值）。上述默认值为本规格锁定口径，调整须经评审。

## 范围排除

- Agent 会话内容/会话视图（story Out-of-Scope，T-003 划界：不含 run/任务级执行状态展示，后者由 FR-0303 承载）。
- 各阶段流程语义、测试/实施分离、FULL/RGR、CI、安全门、发布/归档的重写（全部继承 v0.8 合同，FR-0297 不重写）。

- 公网多租户、复杂 RBAC、团队协同编辑、分布式多节点调度、插件市场、第二语言 adapter、通用多 registry 部署平台、图形化流程编辑器、通用包管理 GUI（FR-0314.1 只要求本机单用户鉴权；FR-0290 明示沿用已配置环境）。

- 不以"28 个 API endpoint 齐备/页面全部画好"为完成标准（story 验收脚本：单条真实纵向闭环可演示）。
