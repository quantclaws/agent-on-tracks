## Human 已定方向（v0.10 需求输入，非协商项）

### D1. SPA 架构

工作台采用单页应用：功能区切换、tab 开闭、文档切换、保存均不经整页刷新（对应 louke AC-NFR0200 的"无闪烁/焦点丢失"）。技术选型（原生 ES modules 或构建链）留给 M-DESIGN 裁定——需求层只锁定"SPA 交互模型"与无整页跳转；louke 当年否决 React/Vite 构建链的理由（无构建步骤、资产可审计）供 Archer 参考但不构成约束。

### D2. 登录与身份

沿用 louke 现有登录 UI 设计：`louke/web/app.py:_login_shell`（约 3280 行起）——双栏 auth shell，左侧 hero 图（`louke/web/assets/*.jpg`）+ 标语 + 图片署名，右侧登录面板（`登录 | 注册` tab、用户名 + 密码字段、聚焦环、移动端折叠为单栏），错误提示行内展示。tracks 侧固定为：

- 允许记住登录态：持久 HttpOnly `SameSite=Strict` 会话 cookie（louke 与 tracks v0.9 均为 7 天滚动窗口），"记住"由持久 cookie 承载，不做额外复选框（除非 story 阶段另有决定）。
- 初次登录要求输入名字（显示名），持久化在服务端并与会话绑定；该名字此后用于与 agent 的对话与留痕（讨论 speaker 标签、approval/anchor 的 actor、assignment 称谓）。
- tracks 边界不变：本机单用户（RP-01），名字是身份标注而非多账号系统；注册 tab 与 louke 的多用户 store 不引入本版。
- 现状差距：v0.9 的登录页是功能壳（`_login_body`），仅密码字段，actor 固定为 `local-user`（`server/app.py` `_LOCAL_ACTOR_FALLBACK`）。

### D3. 左侧 tab 条 + sidebar + main area（结构需求，固定）

以下语义逐条引自 louke v0.13-001 spec.md（FR 原文条款），作为 v0.10 chrome 的固定需求：

1. 三段式布局：垂直 toolbar、可多级菜单 sidebar、含多个 tab 的 main panel；三区相对位置在所有上下文一致（AC 级别：布局骨架不出现第二个变体）。
2. toolbar 自上而下顺序：功能项区；自下而上：Gears、Accounts；仅图标 + hover tooltip，命中区 ≥32×32px；图标顺序固定，不支持拖拽重排（v0.13 明示排除）。
3. 切换 toolbar 项 → sidebar 切换到对应导航树，main panel 打开或激活对应 tab；两类动作在同一次切换内完成，不存在"只换 sidebar 不开 tab"的中间态。
4. 已打开的各功能 tab 共存、切 toolbar 不被关闭；重复点击同一 toolbar 项激活已有 tab（唯一实例，按 tab key）；用户主动关闭是唯一关闭路径；无"关闭所有"全局动作；tab 集合只在浏览器内存，不跨会话持久化。
5. Gears 只打开/激活 Settings tab、不改变 sidebar 内容；Accounts 弹菜单，本版仅含 logout，logout 后浏览器不残留凭据。
6. 降级规则：sidebar 树节点、main 内容、tab 标签的未知/缺失值一律显式降级展示（可读 NotFound / "未知"标记），不崩溃、不 500、不留空白 tab（v0.13 一等需求）。

louke 的 tab 集合（Chat / Dev Docs / End User Docs / Wiki / Runs）是其产物结构的映射；tracks 的功能项候选（Projects、Runs、Docs、Review、Todos、Settings、Account）在 story 阶段收敛，本文档不锁定具体图标集合，只锁定上述联动结构。

### D4. 需求文档中心（Vditor 查看/编辑 + 分屏 + inline discussion）

承接 v0.9 Human 裁定（Vditor 本版仅基础集成，扩展定制留待后续）的下一版落地：

- 文档浏览：以 `.tracks/projects/<version>/` 六件套（story/spec/acceptance/architecture/interfaces/test-plan）为对象，目录树 + 文档渲染；Vditor `ir` 即时渲染模式（资产已 vendor 同源，`server/static/vendor/vditor/`）。
- 编辑：经既有 `POST /api/runs/{run_id}/docs/{doc}/edits`（edit_material 修订流程）写回，产生新 revision，不绕过批准绑定（FR-0308）；显式保存按钮、dirty 才 enabled；乐观并发（revision/mtime 冲突 → 409 + 重载放弃/强制覆盖两选项，louke v0.9 FR-0500 模型）；写失败编辑内容不丢。
- 分屏：多文档 pane（louke v0.10 FR-0400：最多 4 列，每 pane 独立文件选择器与工具栏，pane 独立加载不同文档可对照）。
- inline discussion：呈现与导航（显示/隐藏切换、下一个 discussion、只看未决 `[resolved]` 过滤；RESOLVED 仅发起人）；讨论以 Markdown quote marker 随正文持久化（louke v0.7-003 协议：嵌套 `>`/`>>`、speaker 由加粗名决定、五元组 thread 模型）；UI 写回经服务端结构化操作，客户端不手写协议拼接（louke v0.8 discussions/mutate 模式）。
- 降级：Vditor 加载失败回退 textarea（louke v0.10 NFR-0100 韧性策略）。

### D5. run 详情（13 阶段时间线）——视 spec 容量决定

若容量允许进 v0.10，否则整包延后 v0.11：louke v0.14-004 的 Project Status 模型——顶部当前节点卡片（责任方/attempt/运行时长/唯一主要动作）+ 13 阶段线性时间线（M-START → … → M-PUBLISH → M-MILESTONE；每次 attempt 独立节点不折叠，回拨用可辨认回边，视口聚焦活跃节点 ±3）+ 节点详情浮层（起止时间、artifact/revision 跳文档中心）。数据源（`/api/runs/{id}/timeline`、`/ac-chain`）v0.9 已交付，本项是纯前端 + 投影建模工作。

### D6. 接真数据（NFR，加入 v0.10）

以下作为非功能需求整体纳入（louke v0.11-002/v0.13 的验收基线）：

1. 无 mock 数据、无假成功：任何 UI 状态不得由硬编码数据伪造；API 失败必须产生用户可观察的失败反馈（louke AC-FR0202-03/04 的直接移植）。
2. 服务端唯一权威：UI 只消费查询投影与事件流；客户端缓存不得改变状态事实（louke AC-FR1201-02 语义）。
3. 测试分两层：API e2e 验证接口契约；UI e2e（Playwright/Chromium）验证真实浏览器旅程，UI 测试不得以 API 请求替代关键 UI 操作；控件用 `data-testid` 绑定，不依赖 CSS class/DOM 层级。
4. 事件流健壮：SSE 断线按序号补读（louke `Last-Event-ID` 模式），重复/乱序事件不使 UI 倒退。
5. 安全边界：写操作统一 CSRF + `Idempotency-Key`（v0.9 已具备，UI 层遵守同一契约）；秘密经既有 redaction 投影后展示。

## 明确不做（v0.10 范围排除候选）

Chat/Agent 会话流（louke v0.13 Chat 对应物）、模型绑定页、质量面板、i18n、setup 向导/onboarding 门禁、Settings 完整三页——louke 各占独立版本，容量经验表明单版不可兼得。跨会话 tab 持久化、拖拽重排 toolbar、WebSocket、多用户/公网边界维持不变。

## 约束与既有事实（tracks v0.9 盘点）

- 页面封闭集 8 个（`PAGES` in `server/pages.py`）：login/overview/projects/run_new/run_detail/review/todos/release；API 面完整（projects/runs/timeline/ac-chain/todos/docs/diff/edits/events SSE）。
- 认证：scrypt 密码 + 7 天滚动会话 + CSRF 头 + 写操作幂等键；脱敏（redaction）投影已交付。
- supervisor 单活动 run 串行 + hotfix 换队语义（FR-0296）已在运行时层锁定，UI 不得发明并发推进入口。
- Web 层不得直接耦合 runtime；HTTP 改动经命令服务（v0.9 spec §技术选型约束，本版继续继承）。
